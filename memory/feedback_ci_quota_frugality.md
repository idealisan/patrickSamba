**CNB CI 额度每月只有 160 核心小时，必须抠门使用。**

**Why:** 2026-08-09 项目所有者直接指出「你们用 ci 用的太多了」。此前团队习惯是每个 agent
每 10~15 分钟推一次、每条分支都开 PR、还额外开探针分支专门跑 CI 做实验，多个 agent 并行时
一小时能烧掉几十条流水线。实测单条流水线 `metricCoreHours ≈ 0.14`（约 130 秒 × 4 核），
**160 核心小时 ≈ 1140 条流水线**，看着多，但 8 个 agent 各自频繁推送时消耗极快。

**How to apply:**

- **本地门禁先跑完再推。** `sh test/ci/check-test-compile.sh`（约 18 秒，四平台 × 全 tag，
  含 `_test.go`）+ `gofmt -l .` + `go vet ./...` 在本地全绿之后才 push。
  用 CI 当「第一次编译检查」是最贵的用法。
- **攒到一个可评审单元再推**，不要每个小改动都推。§7.2 的「尽快提交」指的是
  **commit**（本地、免费），不是每次都 **push**（触发 CI、要钱）。两者不要混为一谈。
- **探针实验用 `go test -overlay`，不要开分支推上去跑 CI。** overlay 能在工作树零修改的
  前提下替换任意文件做配对对照/变异测试，本地几秒出结果。
- **纯文档改动不该触发 CI**（`ifModify` 排除法，见 PR #143）。
- **不要「重跑一次看看」。** 判据假红时重跑是双倍浪费且什么都证明不了；正确做法是抓
  runner 原始日志定位根因（`cnb build get-build-stage` / `build-runner-download-log`）。
- **给共享门禁加新关要算账**：每加一个 stage，之后**每一次** push 和 PR 都要为它付费。
  只有当它能挡住真实事故、且本地跑不了时才值得加。

**不该省的地方**（省这些是假节约）：
- 合并前确认目标分支 CI 绿 —— 这是唯一能挡住 main 变红的关口。
- 反向对照/变异测试 —— 在**本地**用 overlay 做，不占 CI，但绝不能因为「省 CI」就不做。
