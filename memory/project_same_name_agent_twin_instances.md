同一个 node 进程内可以同时存在**两个同名 agent 实例**，它们**共写同一份 `agent-<hash>.jsonl`**。
2026-08-09 22:04~22:12 实测于 `docs-honesty`：对方在我停顿的每一分钟里各产出一条 assistant 发言
（22:04:44 / 22:05:29 / 22:06:09 / 22:07:54 / 22:08:36 / 22:08:52 / 22:09:16 / 22:09:35），
其中 22:05:29 那一条当场推出了合并提交 `df3e388`。

**Why**：这是「第二执行者」谜团的一种真实形态，而现有的两条判据都识别不了它：

1. `grep -h sessionId /root/.codebuddy/sessions/*.json | sort | uniq -c` = **1**（不是双进程同挂 session，
   `project_dual_codebuddy_session.md` 那条覆盖不到）；
2. `ps` 里 codebuddy 只有 **1 个** node 进程；
3. AGENTS.md §10.3 的不变量「按角色名归并 `agent-*.jsonl`，窗口内每角色恰好 1 个实例」
   在这种形态下**恒为真却毫无信息量** —— 两个实例共用一个文件，计数当然还是 1。

**How to apply**：

- **唯一可用的判据是「日志内两条时间线交错」**：在自己的 `agent-*.jsonl` 里按 `role=assistant`
  抽出发言，逐条问「这句是我写的吗」。出现你没写过的发言 = 双实例。
  这也意味着：**agent 日志不能用来证明「某个 git 操作是不是我做的」** ——
  它只能证明「是这个角色做的」。§7.3.4 的自查第 1 条要按此降级理解。
- **自查会出现「一半是我一半不是」**：本次 `be686ba`/`d0beb47` 是我、`df3e388` 不是。
  别看到一条命中就收工，也别看到一条不命中就广播。
- **处置是单方面停手 + 上报，不是 kill**：对方的产出未必是坏的（本次全程 append-only、
  `--is-ancestor` 逐段 rc=0 零丢失，还替我修掉了一句我刚发现的 PR 描述假话）。
  停手的理由是**避免两个实例对同一分支/同一 PR 描述对撞**，不是它做错了。
  由 team-lead 指定哪个实例继续。
- **按「已观测到的危险」记，别安因果**：本次双实例**没有**造成任何丢失或冲突。
  同期还有一起「21:20:38 有人在 `/work/oscap-wire` 跑 rebase」的悬案，
  把 docs-honesty 日志 21:10~21:35 全扫过后**查无实据**，就**不要**顺手安到双实例头上。

**附带一条同源教训：会话摘要压缩后，你的记忆比你的日志短。**
本次我的上下文摘要截断在 `7acf00d`，而日志显示我自己在 21:33~21:47 还建了 `/tmp/mb-merge`、
写了「抢救 4 个孤儿记忆」、推了 `be686ba`/`d0beb47`。
差点第 4 次犯 §7.3.4 那个「我不记得做过 = 不是我做的」的错。
**自查必须查日志，不能查记忆**；查法是在自己的 jsonl 里 grep 那个 SHA / 路径 / 提交信息片段，
取首次出现的时间戳。

**顺带一个在做上面这件事时新踩的 zsh 坑（同属「成功回显 ≠ 事情真的发生」家族）**：

```sh
git push origin $C:refs/rescue/xxx        # ❌ zsh 下失败
git push origin "${C}:refs/rescue/xxx"    # ✅
```

zsh 把 `$C:r` 里的 `:r` 当成**历史/变量修饰符**（去扩展名）吃掉了，
refspec 变成 `<sha>efs/rescue/xxx`，报「源引用规格 …efs/rescue/… 没有匹配」。
这次是**响雷**（推送失败、看得见），但同一个变形在别的命令里可能静默生效，
所以凡是 `$VAR:` 紧跟字母的地方一律加 `"${VAR}"` 花括号。
