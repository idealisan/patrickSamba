文档里凡是「**写下时正确、但已知会很快变**」的陈述，一律圈成带 `BEGIN`/`END` 标记的可替换块，
块内写**可复算判据 + 事实截止时间戳**，不写形容词。**替换责任归「让事实变了的那个 PR」，
且必须与造成变化的代码在同一次合入。**

**Why**：2026-08-09 v0.2.0，docs-honesty 要写「oscap 尚未接线」，而接线 PR 就在几十分钟后。
他没有在「说没接线」和「说要接线」之间二选一，而是在 `CHANGELOG.md:217` 放了

```
<!-- BEGIN-OSCAP-WIRING-STATUS：接线 PR 一合入 main，整段替换本块，不要散改别处 -->
**尚未接线（…本块截至 2026-08-09 18:35 CST 为当下事实，接线 PR 合入后整段替换）**
```

块内是四条可复算判据（`go list -deps` 计数、包外真实调用点数…）而不是「基本完成」这类词。
这把「记得回来改」从人的记忆里挪进了文件，且下一个人 grep 得到。

归属那一半是我先判错、后更正的：我最初派给「写文档的人」，正确的是**谁让事实变了谁改**。
分成两个 PR 的话，两次合并之间 main 上就摆着一句已经不成立的话——而这恰是审计要消灭的东西。
可替换块**不是给「以后某个人」准备的，是给推翻它的那个 PR 准备的**。

**How to apply**：

- 判据：**记录既成事实（有日期、有决策人）→ 可以带版本号**；**表达将来意图 → 去掉版本号**，
  改写成「当前事实 + 优先级」。「v0.3.0 会做 X」在计划一改的那刻就是假话，而且没人回来改它。
- 块内至少给一条**能一行命令复算**的判据，让读者不必相信作者。
- 合并排序会因此产生耦合：**放块的 PR 必须先合**，否则推翻它的 PR 手上没有块可替，
  改出来必然和 main 对不上（会变成 add/add 冲突）。排队时要显式安排这个顺序。
