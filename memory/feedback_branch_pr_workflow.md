name: 团队改用独立工作目录 + 独立分支 + PR
description: v0.1.0 之后每个 agent 必须有自己的 git worktree 和分支并走 PR 合并；worktree 才是根治互相干扰的手段
type: feedback
---

**从 v0.1.0 发布之后的所有开发开始，团队隔离是「独立工作目录 + 独立分支 + PR」三件套，
缺一不可。禁止直接向 `main` 推送。**

用户原话（两次，先后补充）：
1. 「从下个版本的开发开始，团队中使用自己独立的分支开发，不要共用一个分支了，
   走提 PR，合并的流程。」
2. 「每个人创建自己的工作目录，隔离工作就好了。目的是为了各自工作互不干扰。」

**Why:** 共用一个工作树 + 共用 `main` 已经反复造成两类真实事故：

1. 别人未提交的中间态让 `go build` 报出根本不存在的错误——真实发生过某 agent
   分两步做重命名，中间约 1 分钟工作树是 `undefined: xxx`，另一个 agent 撞上后
   排查了一个不存在的 bug。v0.1.0 收尾期又发生一次（删 `User.UID/GID` 死字段时，
   `config` 改了而 `auth/static.go` 未跟改，持续数分钟，全队构建皆红）。
2. 不合规/半成品代码可以一路畅通进 `main`，直到发布前才被发现——
   v0.1.0 发布前就撞到 CI 的 gofmt 门禁在 HEAD 上已经是红的，
   以及 `test/` 目录因为 build tag 从未被任何校验覆盖过。

**关键认知：分支只隔离提交历史，不隔离文件。** 我最初只加了分支规则并在文档里写
「分支不隔离工作树，所以文件所有权照旧」，用户直接指出正解是**每人一个工作目录**。
worktree 消灭第一类事故，PR 拦住第二类。

**How to apply:**

- 开工第一件事就开自己的 worktree，之后所有操作都在里面做：
  `git -C /workspace worktree add /work/<角色> -b <角色>/<主题> origin/main`
  `/workspace` 留给 team-lead（停在 `main`）。用完 `git worktree remove`。
- 各 worktree 共享同一个 `.git` 对象库，不占额外下载；一个分支只能被一个 worktree
  检出，天然强制「一人一分支」。
- worktree **隔离文件但不隔离端口**，专属调试端口的规矩照旧。
- 分支名 `<agent 角色>/<简短主题>`，如 `auth/smb30-encryption`。
- 「尽快提交尽快推送」的纪律**不变**，只是推送目标从 `main` 变成自己的分支——
  环境随时崩溃，未推送的工作依旧永久丢失。
- PR 要小、能独立编译通过，一个 PR 只做一件事。合并前 CI 必须绿。
- 对**自己的**分支允许 `--force-with-lease`（不是 `--force`）；对 `main` 一律禁止强推。
- 文件所有权划分依然有效：worktree 让你不会*物理上*破坏别人，但两人在各自分支改同一
  文件，合并时照样冲突。
- 规则已写入仓库 `AGENTS.md` §7.3（该文件是本项目最高准则）。
