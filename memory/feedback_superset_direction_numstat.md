合两份同源文档（记忆文件、AGENTS.md、CHANGELOG 这类）之前，
**先对每个文件跑 `git diff --numstat A B -- <file>` 判方向，再决定取哪侧**：

- `x 加 / **0** 删` → B 侧是 A 的**严格超集**，可以 `git checkout B -- <file>` 整份取。
- 只要 `删 > 0` → B 侧有净删，它可能是**子集或旧稿**，
  必须以另一侧为基、只改需要改的那几行。

**Why:** 2026-08-09 22:2x 收敛三条记忆落库链时，我本来打算直接 `git merge` 自己的
`ff501cd4`。它与目标只有 3 处冲突，看起来「冲突少 = 差异小 = 随便取哪侧都行」——
实际上 `MEMORY.md` 那侧的 numstat 是 **4 加 / 6 删**，我那份**少了对方后来新增的
2 条索引条目**（`zsh_wordsplit`、`probe_placement`）。按「冲突里取自己那侧」解，
就会静默删掉两条索引，而合并结果 rc=0、`git status` 干净、没有任何提示。
同一批里 `project_rescue_ref_inflight.md` 是 **30 加 / 0 删**，那侧才是真超集。
**「冲突数少」与「取哪侧都行」是两件完全无关的事。**

**How to apply:**

- 冲突文件与非冲突文件**都要**判方向 —— 静默回退恰恰发生在**不进冲突列表**的文件上
  （见 `project_silent_success_failures.md` 第 14 条：净删 75 行，零冲突）。
- 批量判方向的写法：

  ```sh
  git diff --numstat A B -- <目录>/ | awk '$2>0 {print "  ⚠ 净删 "$2" 行: "$3}'
  ```

  有输出就说明 B 侧对这些文件不是超集，**逐个人工确认是有意替换**
  （整行改写会记成 1 删 1 加，属正常；`-62` 这种量级基本都是旧稿）。
- 落库前后各跑一次：合之前判方向，合之后跑
  `git diff --numstat origin/main HEAD -- <目录>` 看删除面。
- 推给别人吞的收敛提交，要做成对方分支头的 **ff 子孙**
  （`git merge-base --is-ancestor <对方头> <我的提交>` rc=0），
  并在消息里附「相对对方头的完整 numstat」——**让对方能一眼看完全部净变化**，
  这比说「我做了收敛」有用得多。
