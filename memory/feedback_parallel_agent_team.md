在 stupidSamba 项目上推进工作时，**默认就要组建 3~5 个子 agent 的团队并行开发**，
不要一个人串行地写。

**Why:** 用户原话是「现在的工作速度太慢了，你必须使用 3~5 个子 agent，分工合作形成团队
去完成工作，从而加速开发进度」。在此之前用户已经提示过一次「需要的话你应该使用子 agent
并行加速开发」，说明这是他反复强调的诉求，不是一次性的临时指令。项目本身的
`AGENTS.md` §7.1 也把并行分工写成了准则，并按分层给出了 5 个 agent 角色划分
（wire / auth / vfs / server / mdns）。

**How to apply:** 按 `AGENTS.md` §5 的分层切分任务，**先定接口契约再并行实现**。
目录变大时要**按文件再切分**所有权（`internal/smb/command` 已经这么切过），否则会互相覆盖。

## 三层隔离（缺一层就出事，逐条都是踩出来的）

1. **工作目录隔离**——用户原话：「每个人创建自己的工作目录，隔离工作就好了。
   目的是为了各自工作互不干扰。」每个 agent 用自己的 git worktree：
   `git -C /workspace worktree add /work/<角色> -b <角色>/<主题> origin/main`，
   `/workspace` 留给 team-lead。这是**根治**共用工作树污染的唯一办法。
2. **分支隔离 + PR**——用户原话：「从下个版本的开发开始，团队中使用自己独立的分支开发，
   不要共用一个分支了，走提 PR，合并的流程。」禁止直接推 `main`。v0.1.0 之后生效。
3. **端口隔离**——每个 agent 专属调试端口（例 4451~4455），否则互相抢 445/4445。
   worktree 隔离文件但不隔离端口。调试二进制名必须 ≤ 15 字符，否则 `pkill -x` 静默失效。

**关键认知**：分支隔离的是**提交历史**，不隔离**文件**。只做分支不做 worktree，
「别人未提交的中间态让我的 `go build` 报出根本不存在的错误」这个坑照样会踩
（已真实发生多次，有人因此排查了一个不存在的 bug）。

## 给子 agent 写 prompt 的纪律

- prompt 必须**自包含**：它看不到 team-lead 的对话历史，项目背景、环境坑、
  提交纪律、文件所有权都要重复写一遍。
- 必须写死「能改哪些文件 / 明确不能改哪些」。
- agent 需要改别人的文件时，要求它发消息给 team-lead 协调，不要自己动手。
- 作为 lead，收到 agent 的调研结论后**自己消化再下发具体规格**（文件路径+行号+改什么），
  不要写「based on your findings」这种把理解甩回给 agent 的指令。
- **要自己复核 agent 的交付**，不能只信报告。已发生过：agent 报告「修复完成」，
  实际只覆盖了规格的一半（另一条协商路径的同类漏洞原样存在）。
