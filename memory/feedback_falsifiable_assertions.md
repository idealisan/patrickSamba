---
name: 验收判据必须可证伪，探针本身要有反向对照
description: 安全属性的测试不能用"功能还能用"当判据；每加一个断言要先证明它抓得住失败
type: feedback
---

写验收/门禁时，**先问"这条断言在功能被破坏时会不会红"**，答不上来就说明它是摆设。

**Why:** 本项目连续栽在这一类盲区上，都不是代码写错，是"没人以正确的方式验证"：

- 加密验收原本的判据是「smbclient 能读到文件内容」。可明文旁路时内容照样读得到——
  `encryption_required: true` 的服务被 `smbclient -m SMB2_10` 降级成全程明文，
  验收脚本一声不吭地绿。判据对它要防的那个失败**完全无感**。
- `dialect_test.go:88` 直接调 `SMB300.ServerCapabilities(true)`，绕过真实调用路径：
  函数本身是对的，但没人以正确的方式调用它。单测越像模像样越容易掩盖这种事。
- CI 的 gofmt 门禁只在推到 main 之后才跑、又没人盯结果，"门禁看着存在、实际拦不住"。

team-lead 明确认可过的两条处置：**失败用例要如实 FAIL，不 skip 不注释**
（被 skip 掉的失败用例等于不存在）；**门槛判定与附加用例解耦**
（否则要么附加用例拖垮门槛，要么有人为了让退出码变绿去动门槛）。

**How to apply:**
- 安全属性（加密/签名/拒绝路径）不能用"业务还能用"来判定，要观测**机制本身**：
  看网线上的字节、看服务端日志里的关键字段、看返回的 NTSTATUS。
- 每加一个探针/门禁，**同时跑一次反向对照**，用已知失败的输入证明它会红，
  并把这个反向对照的结果写进注释或提交信息里——否则下一个人无从判断它是否还有效。
- 写"拒绝"用例时，光断言客户端报错不够，还要断言**没有旁路**
  （例：被拒之后网线上不许出现任何业务命令的明文帧）。
- 构造用例前先确认它真能走到被测代码：把门槛设在别处（如 `min_dialect: 3.0`）会让
  请求在更早的一层就被挡掉，测的根本不是你以为的那段逻辑。
- **配额/上限/阈值类字段必须取阈值两侧各测一次**。真实案例：`quota_bytes` 探针只用了
  2 TiB（大于宿主 256 GiB 的盘），看到"上报 256 GiB"就记通过——可这个结果在
  `quota_bytes` 是**死字段**时一模一样，探针零证伪能力。改成 10 GiB（小于宿主）
  才验出字段真的生效，并顺带发现"配额小于宿主已用量时空共享上报 0 可用"这个
  会让 macOS 直接判定磁盘已满的坑。**只测不触发限制的那一侧，等于没测。**
  本项目已经出过两次死字段（`time_machine_max_size`、`users[].uid/gid`），
  遇到配置项先默认怀疑它是死的，用能让它生效的取值去证明它活着。
- **反向对照本身也会是假的，所以要用变异测试验证「反向对照真的会红」。**
  真实案例（tm-lease，oplock break 推送）：验证 `sendUnsolicited` 走 writeMu 的用例
  写成「先锁 writeMu → 再发推送 → 断言推送挂住」，看着是标准反向对照。
  但传输用的是 `net.Pipe`（**同步无缓冲**），没人读的时候写本来就阻塞——
  「推送没完成」既可能是被锁挡住、也可能只是没人读，两者分不开。
  把 `writeMu.Lock/Unlock` 注释掉，这个用例**照样通过**（而且整个测试进程挂死 5 分钟）。
  改成「先挂上读方 → 再锁 → 再发」之后，唯一还能挡住推送的才只剩锁。
  做法：`go test -race -overlay <json>` 把被测函数换成去掉保护的变体，
  确认目标用例真的 FAIL（这里还额外让 race detector 指出了共享的 `Transport.whdr`）。
  overlay 不落盘、不影响共用工作树里的其他人。
- **文档里的状态陈述同样要可证伪，并且要带时间戳圈成可替换块。**
  文档不是测试，但「当前尚未接线」「暂不支持 X」这类**会很快变**的陈述，
  和一条断言一样需要可复核，否则它过期之后没人知道该改哪里，
  最后就退化成含糊的「部分支持」——那正是本项目要防的「结论对、证据假」。
  2026-08-09 `docs-honesty` 给出的写法值得照抄（`CHANGELOG.md`）：

  ```
  <!-- BEGIN-OSCAP-WIRING-STATUS：接线 PR 一合入 main，整段替换本块，不要散改别处 -->
  **尚未接线（本版本的实际行为边界；本块截至 2026-08-09 18:35 CST 为当下事实）**
  - 判据 1：`go list -deps ./cmd/stupidsamba | grep -c oscap` = 1
  - 判据 2/3/4：…（可复算命令，不是形容词）
  ```

  三个要素缺一不可：**① 时间戳**（把它限定成某一时刻的事实，而不是永恒真理）；
  **② 可复算判据**（读者能自己跑一遍，而不是信你）；
  **③ 唯一替换点的标记**（改的人整段替换，不必满文档追着改，也不会漏掉某处）。
  附带好处：它把「现在没做」与「马上要做」从互相否定变成可以并存，
  两个 agent 的叙事冲突不用开会拍板就消解了。

  **⚠️ 三要素齐全仍会翻车，必须补第 ④ 条：合入前重跑一次判据。**
  实测反例（同一天、同一个人，最短腐烂周期 **90 秒**）：一条登记「freebsd 那一档
  没有反向对照，`grep -c freebsd` → 0，实测 18:59 CST」的断言，三要素一个不少，
  但补丁 `08cfa27` 在 **19:08:59** 就已合入，而该断言所在的 PR 19:10:29 才合入——
  **它进入 `main` 的那一刻就是假的**。
  ④ **合入前重跑**：任何带「实测 <时间>」的断言，进合并队列前把判据命令再跑一遍。
  这也是判据必须「能一行复制执行」的第二个理由（第一个是给读者复核）。
  高危类型是**登记别人该修的缺口**——你写它时那个人正在修，而且多半比你先合。
  ⑤ 顺带：块头若写「同类块共 N 处」，**N 本身也是待核断言**。实测写「三处」漏了一处，
  漏掉的恰是接线人点名要改的那处。
  ⑥ **grep 出来的命中分三类，别只分两类**：① 活断言＝成对 BEGIN/END，整段替换；
  ② 范例引用＝孤立一行 BEGIN（进度板、本记忆里引在代码围栏内），不要动；
  ③ **正文交叉引用＝不含 BEGIN/END，只在句子里提块名**（如 README 里「详见 …
  OSCAP-WIRING-STATUS 块」），正文不用改但**块改名/删除时必须同步**。
  初版只分了①②，漏③的原因很典型：**按「有没有 BEGIN」分类就永远看不见 ③**，
  而 grep 照样把它捞出来——分类规则的维度必须覆盖 grep 的召回范围，否则会漏。
  ⑦ **判据本身要选「不会漂」的那种：绑锚点和退出码，不要绑计数。**
  `grep -c` / 行数 / 文件数这类**计数型判据**，任何人多写一行注释就变，
  适合一次性核对，**不适合写进长期文档**。
  实测反例（同一天第三次复发，间隔 **零**）：我写「`grep -c -i freebsd
  test/ci/negative-verify.sh` → **8**」，同一个 PR 里我又给那节加了锚点注释、
  注释里提了三次 freebsd，于是复算得 **11** —— **写断言的人和破坏断言的人是同一个，
  两者躺在同一个 diff 里**，连「合入前重跑」都差点救不了（是逐条复算才发现的）。
  改法：判据写成 `grep -n 'ANCHOR: <名字>' <文件>`（看 rc，不看数）
  加 `sh <脚本>`（看退出码与「N 通过 / 0 失败」的失败数，不看通过数）。
- **有条件时优先做「成对黑盒对照」，它比一堆静态判据强，而且强在意外的一侧。**
  同一份输入只改一个字段，分别喂给**改动前后两个二进制**，把结果并排成表。
  实测（2026-08-09 19:42，oscap 接线验收）：`filesystem_mode` 三个取值
  × 未接线 main / 已接线分支两个二进制 = 六格。
  未接线那排三格全绿，正是「三个取值行为完全一样」的**直接证据**；
  已接线那排 `native` 变红，则排除了「这个探针恒真」。
  **两排缺一不可**：只有上排，全绿也可能是因为开关压根没接线到任何地方；
  只有下排，则证明不了改动前的状态。
  价值在于它绕过了「读者得先相信我会读代码」——原先同一结论只有四条
  `grep` / `go list` 静态判据撑着，属于 C 级证据；成对跑一遍就升到 A 级。
  代价通常只是多编译一个二进制（本例约 20 秒）。
- **区分「环境导致的失败」与「设计导致的失败」，并在文档里写死是哪一种。**
  同一条错误信息，读者的下一步动作完全相反：以为是环境问题就去换盘/换容器重试，
  知道是设计使然才会去改配置。判别要落到源码：本例 `CapDOSAttributes` 分支
  **不看任何文件系统、无条件 `return false`**，所以「POSIX 上 native 必失败」
  与文件系统无关。**写结论时把这半句带上**，否则第一个撞上的人必然白折腾一轮。
- **并发用例要给写方设超时**。`net.Pipe` 无缓冲，收帧方一旦提前 return，
  所有写方就永久挂死——一次本该干净的 FAIL 变成一次超时挂起，极难排查。
  收帧方出错也要**继续排空**而不是提前退出。
