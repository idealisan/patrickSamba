**CI 判据里出现「耗时」「比值」「阈值 N×」就要警惕。** 共享 runner 上一次 GC / 一次调度抢占 /
一次缺页，就能把微秒级的平均值抬高十几倍。正确的修法**不是**放大阈值、**不是**加 build tag、
**不是** `t.Skip`，而是换一个**确定性的观测点**：把「有没有做某件事」从耗时**推断**
改成直接**计数断言**。

**Why:** v0.2.0 发版被 `TestPathLookupScaling` 卡了整轮。它判「50k 耗时 / 1k 耗时 > 4× 就红」，
基准量只有 ~1.5 µs、`iters=20` 取**平均**（均值对长尾抖动毫无抵抗力，一次被抢占就毁掉整批）。
事故 sn=`cnb-v7o-1jviua2rj`：`ff77acb`(绿) 与 `c269b76`(红) 之间**只差一处 THIRD_PARTY.md
文档改动，产品代码逐字节相同**，同一份代码两种结论；同一 sha 的 push 红而 pull_request 绿；
两条流水线相隔 9 秒在同一台 runner（10.235.0.14）上重叠跑。失败表本身就在反证不是回归：
1k→10k 只涨 1.09 倍（真在全扫应当 ~10 倍），50k 那个 21.7µs 是离群点、不是曲线。
处置见 PR #149（squash `d5e11ca`）。

**How to apply:**

- **换观测点**：想测「有没有走某条慢路径」，就在那条路径上加一个包内
  `var xxx atomic.Int64` 计数器（不导出、快路径零开销，只在已经要做 O(n) 工作的入口自增一次），
  断言**次数**而不是耗时。耗时表**降级成 `t.Logf` 诊断**，并在注释里写清「不许改回判据」——
  否则下一个人会顺手把它变回去。
- **计数器复位用 before/after 差值，不要 `Store(0)`**：这样 `-count=N` 连跑、以及同包其他
  用例先前造成的计数都不会污染结论。代价是该文件**不得 `t.Parallel`**，这条前置约束必须
  写进注释（计数器是进程全局的）。
- **反向对照是硬要求**：必须有一条断言「计数 > 0」的用例（本例：查一个只有大小写不同的
  名字 ⇒ 必须发生全扫）。**一个永远读到 0 的计数器和没有计数器是一回事。**
- **变异测试要连探针一起变**，不只变被测逻辑。本例三个变异体里最关键的是
  **摘掉 `pathFullScans.Add(1)` 自增本身** —— 它证明反向对照不是摆设。只变被测逻辑的话，
  探针早就掉线了也发现不了。变异体必须**先 `go vet -overlay` 确认能编译**（rc=0），
  否则「红」只是编译错误，判据一次都没被触发。
- **反向对照要防静默退化**：断言构造出来的对照输入确实满足前提（本例断言大小写变体名
  含字母、且在磁盘上确实不存在），否则改了参数之后对照会悄悄退化成正向用例 ——
  判据看着还在，实际一次都没被执行。

**本地复现假红的配方**（PR 里给数字远比讲道理有用，此前全队一直在「重跑一次看看」
和「是不是基础设施抖动」之间打转，就是因为没人能主动复现）：

```sh
(for i in $(seq 8); do (while :; do :; done) & done; \
 GOGC=5 CGO_ENABLED=0 go test -count=12 -run <用例> ./<包>/; \
 kill $(jobs -p))
```

- **只打满 CPU 不加 GC 压力，旧判据 5/5 全绿**，复现不出来；
- 叠上 `GOGC=5` 之后 **12 次里红 1 次**（比值 19.0×，1k=1.964µs → 50k=37.285µs），
  即 **≈8%/次**。这个概率正好解释了它为什么能长期活着：单次重跑大概率变绿，
  于是每次都被归因成「基础设施抖动」。
- 跑完记得 `kill $(jobs -p)` 收掉死循环，并用 `ps -eo pid,pcpu --sort=-pcpu | head` 确认
  没有残留 —— 否则后面所有人的测量都被你污染。

**新旧判据配对对照（`go test -overlay`，工作树全程零修改）**：把旧版测试文件从 git 里取出来
注入回去，在**同一台机器、同一种压力、同样次数**下与新判据对跑：

```sh
git show origin/main:internal/vfs/path_perf_test.go > /tmp/<角色>-oldtest.go
printf '{"Replace":{"/绝对路径/internal/vfs/path_perf_test.go":"/tmp/<角色>-oldtest.go"}}\n' > /tmp/<角色>-ov.json
go test -overlay=/tmp/<角色>-ov.json -count=12 -run <用例> ./internal/vfs/
```

结果：旧判据红 1/12、新判据 12/12 绿且计数列**逐行相同**（36 行全是 `0 / 0 / 20 / 1`），
同期新判据自己的诊断耗时最高摸到 6.322µs（基准 ~1.7µs，已逼近 4× 阈值）——
噪声确实在，只是不再有人拿它判红绿。这比「我认为它是假红」强得多。

**顺带两条操作纪律**：`/tmp` 是全队共用的，临时文件一律带自己的角色名前缀
（有人被别人的 `/tmp/t.log` 骗过，差点误判自己复现了失败）；
`go test ... | head` 之后的 `$?` 是 `head` 的退出码，先重定向到文件再判。
