文档诚实性审计不能只往「有没有夸大」一个方向查。**反向的失真同样是错，而且更隐蔽，
因为它读起来很谦虚，抽查时会通过。** 2026-08-09 v0.2.0 发版前审计逮到**七种**形态
（第 5~7 条是收口轮追加的，其中 5 和 6 都是**我自己犯的**，不是别人的）：

**Why:** 夸大会被用户用「我试了不行」当场戳穿，反向失真不会——用户只会绕开这个功能
或换个方案，代价是**沉默的**。所以它能在文档里活很久，而且越谦虚越没人质疑。

**How to apply:** 审计每条断言时，除了问「有没有说大话」，还要问这三句：

1. **「这句『未实现』今天还成立吗？」——谎报未完成。**
   实例：`README.md` 的 Time Machine 节写于 v0.1.0，把 durable/persistent handle
   列在「未实现」并标注「对 TM 影响最大」，而 v0.2.0 的头号新增就是它（PR #20/#40/#29）。
   判据：拿 CHANGELOG 当期章节与 README 的「未实现」清单**对撞**，重合项即命中。

2. **「这是现在的事实，还是接线/合并之后才会发生的事？」——未来时写成现在时。**
   实例：队友转述「POSIX 上 `filesystem_mode: native` 恒定启动失败」，我实跑真二进制
   得到相反结果（rc=124 照常启动）——因为 main 上 oscap **没有运行期消费方**，
   报错逻辑根本执行不到。那个结论只在他**已接线的分支**上成立。
   **纪律：队友转述的「实测」必须问清跑在哪条分支/哪个 commit 上**，
   不同分支的实测结论互相矛盾是正常的，直接抄进文档就成了假话。

3. **「已知问题」是所有文档里最容易腐烂的一节。**
   它天然记录「还没做的事」，而那恰恰是别人此刻正在做的事。
   实例：我写「6 个文件从未被编译过」并附注「若有人修了记得改，否则变成谎报未完成」，
   十几分钟后 `e664a47` 真的在 main 修掉了。**发版前必须逐条重跑判据，
   不能沿用审计当时的结论。**

4. **注释/文档里的「见 X」必须当断言核实——X 可能压根不存在。**
   实例：`test/ci/check-test-compile.sh:113` 写「负向对照见 `test/ci/negative-verify.sh`
   的 freebsd 段」，而那个文件里 `grep -c freebsd` = **0**。我第一遍照抄进 CHANGELOG，
   复核时才发现。**危害方向和前三种相反：它会主动劝阻后来者去补**——
   读到那句的人认为反向对照已经存在，于是不写了。
   判据：凡「见 / 详见 / 参见 + 具体实体名」，都要 `grep` 一次那个实体真的在。
   **续**：这条缺口已于 2026-08-09 19:08:59 由 PR #160（`08cfa27`）补上，
   而且是三向对照（正向 / 反向且报错点名 `not an int` / 旧四平台归因）。
   见第 5 条——我为它写的登记文字比修复晚 90 秒进 `main`，于是自己变成了第 3 条的实例。

5. **可证伪断言必须在「合入前」重跑判据，而不是只在「写作时」跑一次。**
   **Why**：写作时刻为真 ≠ 合入时刻为真。实例是本项目最短的腐烂周期，**90 秒**：
   18:59:00 我实测 `grep -c freebsd` → 0 并写下断言；**19:08:59** 别人把缺口修好并合入；
   19:10:29 我的 PR 合入，把那句**已经变假的**断言带进 `main`。
   要命之处在于这条断言**该做的都做了**——可证伪、带判据命令、带实测时间戳、无形容词，
   照样错了。所以它是**追加**的一条规矩，不是替换原有那条。
   **How to apply**：任何带「实测 <时间>」字样的断言，PR 进合并队列前把它自己的判据
   命令再跑一遍。风险最高的是**「登记别人该修的缺口」**这类断言——你写它的同时
   那个人多半正在修，而且他很可能比你先合。判据命令因此必须**能一行复制执行**；
   不能一行跑的断言，说明它本来就不可证伪，应当重写而不是保留。
   附带一条同源教训：可替换块写「一套 N 处」时，**N 本身也是个待核的断言**——
   我写「三处」，实际是四处（漏了 `AGENTS.md §1.2`，而那处恰是接线人点名要改的）。

6. **排除法只做了一半就下结论——「只有 X」「唯独 X」这类排他措辞是重灾区。**
   **Why**：查了 N 个平行分支里的 N-1 个，就把「这 N-1 个都不行」外推成「剩下那个想必行」。
   前半段有源码行号、有实测，**读者核对完前半段就停了**；错的是那个没带证据的转折词
   （「所以」「因此」「实际只」），而转折词不长得像断言。
   实例（2026-08-09 20:03 自查）：我写「接线后 `filesystem_mode: native` 实际**只对 Windows**
   有意义」，依据是 `probe_linux.go` / `probe_darwin.go` 的 `CapDOSAttributes` 硬编码
   `return false`。**`probe_windows.go` 我根本没打开** —— 打开后发现它的 `CapXattr`
   同样硬编码 `false`（不拿 NTFS ADS 冒充 xattr）。而 native 要求六项全原生，
   所以真相是**三个平台都起不来，没有任何可用平台**，与我写的恰好相反。
   **How to apply**：断言里出现全称或排他措辞时，把 X 也查一遍再写。
   **排他性断言的成本是 N 次检查，不是 N-1 次。**

7. **引用别处的段落用「稳定锚点名」，不要用节号/行号。**
   **Why**：节号会随插入新节而漂移，行号更脆；漂移后就退化成第 4 条那种「见 X 而 X 不存在」。
   做法：在被引用处写一行 `ANCHOR: <稳定名>`，引用方写「见锚点 `ANCHOR: <稳定名>`」，
   并附一条可复制的 `grep -n 'ANCHOR: <稳定名>' <文件>`。
   **How to apply**：锚点要有**反向鉴别力**——把锚点改名后那条 grep 必须查不到（rc=1），
   否则等于没验。已落地两处：`test/ci/negative-verify.sh` 的
   `ANCHOR: freebsd-fallback-files`、`docs/v020-honesty-audit.md` 的
   `ANCHOR: half-done-elimination`。
   **行号引用有两种错法，第二种更隐蔽**：① 行号漂了（人人都知道要防）；
   ② **行号没漂，但指错了地方** —— 点过去确实有代码、确实相关，只是**不构成那句话的证据**。
   实例：我写「native 要求六项全原生（`matrix.go:73-90`）」，那里其实是 `UnsupportedError`
   的**类型定义**（且实际范围是 74-95），真正的判定在 **132-143** 的 `case ModeNative:`
   遍历 `capCount` 收集 `missing`。**判据：引用要指向「让这句话为真的那段逻辑」，
   不是指向「与这句话有关的那个名字」。** 锚点绑的是「那一节」，不是「那几行」，
   所以它同时防住①和②。
   另注：**行号要在读者会看到的那个分支上核**（通常是 `main`），不是只在自己的开发分支上核。

8. **「可替换标记块」只覆盖它自己——别把它当成完备的改动清单（块外腐烂）。**
   **Why**：本项目为接线状态设了四处成对的 `BEGIN/END-OSCAP-WIRING-STATUS` 块，
   约定「接线后整段替换这四处」。四处确实都改对了，但同一件事的**块外**表述照旧腐烂：
   `README.md:287` 的配置表格行仍写「三个取值跑起来行为完全一样／抽象层还没接进数据路径」
   （与同文件已知限制第 7 条**自相矛盾**）；`CHANGELOG.md:194` 的小节标题与其下
   「一句话结论」仍写「一处都还没接进数据路径」「本版本运行行为与 v0.1.0 逐字节等同」，
   而它就在块**上方 40 行**，读者先读到它。两处 `grep OSCAP-WIRING-STATUS` **一个都捞不到**。
   **How to apply**：**按语义扫，不要按标记扫。** 收尾时用被推翻的那句话的**关键词**做全库 grep，
   逐个命中判作用域（合法命中长这样：明写「PR #N 之前」的历史对照、或限定在尚未变更的子集上）：
   ```sh
   grep -rn '行为完全一样\|还没接进\|尚未接线\|没有任何产品调用点\|无运行期消费方' \
     --include='*.md' --include='*.yaml' . | grep -v '^./history/'
   ```
   与第 1~7 条的区别：那些是「判据看错了地方」，这条是「**判据自以为覆盖完备**」。
   顺带一个**不算腐烂**的对照：带时间戳与基线 SHA 的审计快照
   （`docs/v020-honesty-audit.md` 抬头写明「审计时间…／审计基线 `96afd87`」）
   记录的是当时的处置，事后事实变了也**不必改**——判据是它有没有自称「当前」。

**配套做法：给每条能力标注证据强度，替代含糊的「已支持 / 部分支持」。**

| 档 | 含义 |
|---|---|
| A | 目标平台真机端到端实测 |
| B | 第三方客户端协议级实测（impacket / smbclient / go-smb2） |
| C | 仅本仓库单测覆盖 |
| D | 代码存在，但没有任何一关执行过它 |

分档的价值在于**它逼你把 D 档说出口**——「代码写了」和「验过了」用同一个词描述，
正是绝大多数文档失真的源头。
