**2026-08-09，项目所有者口述决定**：「time machine 暂时没有时间真机测试，这个需求先放一放，
先做其他的需求，这个需求从 0.2.0 也作为可选项，不强制要求了。」

**Why:** 手上没有可用于真机验收的 macOS 环境与时间。而 AGENTS.md §2 阶段二把
「macOS 能把 Time Machine 备份到本服务并成功恢复」写成了硬验收标准 ——
在没有真机的前提下，这条标准要么阻塞发布，要么诱使团队用「代码看起来实现了」
冒充「验收通过」。后者正是本项目反复栽过的那类坑（结论对、证据假）。
降级为可选是为了不让一个**当前无法证伪**的标准继续挂在发布路径上。

**How to apply:**
- v0.2.0 的发布检查单里**不含** TM 真机验收；它不是 tag 的阻塞项。
- 已经写好的 Apple 扩展代码（AAPL create context、ADS、`_adisk._tcp` 广播等）
  **保留、不回滚**，继续跑单测与协议级用例。降级的是「验收要求」，不是「功能删除」。
- **文档口径必须如实**：任何地方都不许写「支持 Time Machine」「TM 验收通过」这类
  未经真机证实的表述。正确写法是「已实现 Apple 扩展 X/Y/Z，**尚未在真机上验收**」。
  README / CHANGELOG / AGENTS.md §2 三处都要一致。
- AGENTS.md §2「阶段二」的长期目标**不改**（项目最终仍要支持 TM），改的是
  它与 v0.2.0 的绑定关系。
- 将来拿到真机再验收；在那之前 TM 相关工作排在其他需求之后。
