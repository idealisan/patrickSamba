---
name: 历史痕迹一律保留，不要主动清理
description: 用户把会话导出、测试 Release 等中间产物视为珍贵历史资料，切勿自动删除、gitignore 或"用完清掉"
type: feedback
---

**凡是记录了工作过程的产物，一律保留，不要主动清理。** 这是用户反复表达过的偏好，
不是一次性指令。

**Why:** 用户两次明确纠正过我的"清理"倾向：

1. `conversation-*.txt`（会话导出文件）——我曾误判为误提交并执行 `git rm --cached` +
   加入 `.gitignore`。用户纠正：「会话导出文件是我故意提交的，作为项目历史资料很重要，
   要加进去，以免丢失记录」。
2. `v0.1.0-test` 测试 Release——releng 计划验证完就 `--delete --delete-tag` 清掉，
   我照转了这个方案。用户纠正：「跑 v0.1.0-test 但是别删，如果通过再发一个不带 test
   后缀的不就行了，干嘛要删，这是珍贵的工作记录和历史资料」。

背后的逻辑是一致的：**保留的成本几乎为零，丢失则不可逆**。这与本项目
「容器随时崩溃、仓外一切不可信」（AGENTS.md §10）的处境高度相关——用户对
"丢记录"这件事有很强的警惕。

**How to apply:**

- 永远不要删除仓库里的 `conversation-*.txt`、`history/` 快照，或把它们加入 `.gitignore`。
- 测试性的 tag / Release / 构建产物**做完就留着**，不要"用完即删"。
  需要正式版时另发一个干净的，而不是回收测试版的位置。
- 提出方案时，默认选项应当是"保留"；如果确实认为该删，先说明理由并征求同意，
  不要把删除写进计划里当作理所当然的收尾步骤。
- 反过来，清理**临时构建中间物**（`/tmp` 下的 worktree、`dist/` 重建产物）不受此约束——
  区别在于它们不记录任何工作过程。
